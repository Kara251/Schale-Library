# セキュリティ解説

## 現在のアーキテクチャ（2026-08 移行後）

セキュリティ面は「Strapi プラットフォーム + 自前実装レイヤー」から「完全自前の Worker」へ収斂し、Strapi 系依存（axios/ajv パッチ、admin パネルの露出面、poweredBy フィンガープリント）は廃止とともに消滅した。

## 実装済みのコントロール

| コントロール | 実装 |
|--------------|------|
| 認証 | users テーブル + PBKDF2-SHA256（21 万回反復、WebCrypto）; セッションは D1 のテーブル照会で即時失効 |
| セッション cookie | httpOnly + Secure(本番) + SameSite=Strict、TTL 8h |
| パネル認可 | すべての /panel 書き込みルートは fail-closed のセッション検証 + ロール ホワイトリスト |
| ログイン レート制限 | CF-Connecting-IP（エッジで信頼されるヘッダ）、D1 カウンタ、10 分あたり 30 回 |
| 入力バリデーション | コレクション ホワイトリスト + フィールド ホワイトリストの二重チェック、未登録フィールドは 400 で拒否 |
| アップロード | マジックナンバー スニッフィング（jpeg/png/webp/gif）、SVG 無効、4/8/12MB の段階制限 |
| CSV エクスポート | `= + - @` で始まるセルには `'` プリフィックスを付与して無効化 |
| リッチテキスト | フロントエンドで DOMPurify ホワイトリスト サニタイズ（引き継いで維持） |
| 外部リンク | http(s) scheme ホワイトリスト（DB 格納時と描画時の二層） |
| 監査ログ | すべての書き込み操作を admin_audit_logs に記録、エクスポートはページネーション/フィルタ対応 |
| 起動時アサーション | シークレット欠落/プレースホルダは即座に例外（fail-fast の精神を引き継ぎ） |

## 既知の残留リスク（低リスク、受容）

- フロントエンド CSP に依然 unsafe-inline/unsafe-eval が含まれる（OpenNext 移行後に自前ミドルウェアで nonce 強化予定、計画書 S3 参照）
- image-proxy のホワイトリスト ドメインはポート制限なし（B站 CDN の固定ドメインのみで、攻撃面は極めて狭い）

## 依存監査

Strapi 系 advisory は廃止とともに消滅。`pnpm audit` を通常どおり実行すればよく、allowlist スクリプトは不要。
